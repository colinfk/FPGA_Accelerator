## 本次学习内容

### MAC 的数学与硬件位置

- MAC（Multiply-Accumulate）的基本关系为 `Y = A × B + C`。
- 卷积和全连接层可展开为多个输入与权重乘积的累加；PE 通常以乘法器和累加器为核心。

### 位宽与补码

- 对于全精度乘法，`N bit × M bit` 的乘积通常需要 `N + M bit` 保存。
- 4 bit 无符号的 `15 × 15 = 225` 需要 8 bit；该例仅适用于 unsigned 数据。
- N bit signed 补码范围为 `-2^(N-1)` 到 `2^(N-1)-1`；例如 `4'b1110 = -2`。
- 常见 AI 数据通路是 `INT8 × INT8 → INT16 product → 更宽的 accumulator`。

### 累加器位宽

- 连续累加 K 个完整乘积时，常用估算为：`ACC_W ≥ PROD_W + ceil(log2(K))`。
- 例如 16 bit product 累加 256 项，基础估算为 24 bit；是否还需更宽应结合 bias、缩放、实际范围和溢出策略判断。
- 工程上常用 INT32 accumulator，以留出范围余量并适配接口/资源，但它不是所有设计的固定答案。

### 工程认识

- 理论位宽与工程位宽不同；选择还会受 DSP 映射、时序、功耗和系统接口影响。
- FPGA 内部信号位宽不要求是 8 的倍数。

### SystemVerilog signed、位宽与数据通路

- `logic [W-1:0]` 默认按 unsigned 解释；`logic signed [W-1:0]` 以补码解释。二者不改变 bit pattern，只改变其数学含义。
- 同一 bit pattern `4'b1110` 可表示 unsigned 的 14 或 signed 的 -2；在表达式中混合 signed/unsigned 会导致风险。
- unsigned 扩展时高位补 0；signed 扩展时复制符号位。例如 4 bit signed 的 `1011`（-5）扩展到 8 bit 后应为 `11111011`。
- MAC 数据通路应显式呈现为：signed input → product → 符号扩展 → accumulator → 后续量化；不依赖工具的隐式 signed/位宽推导。
- 直接写 `acc <= acc + a*b;` 容易隐藏中间表达式的位宽和 signed 属性。参数化 MAC 应使用明确类型和位宽的中间 product，再进入累加器。

### 参数化累加型 MAC、流水线与验证

- 参数化 MAC 用 `DATA_W` 描述输入精度，用 `PRODUCT_W = 2 * DATA_W` 描述完整乘积位宽，并用独立的 `ACC_W` 容纳多次累加。
- MAC 是带状态的单元：`a × b` 可以是组合计算，而 accumulator 必须由寄存器保存。
- 接口控制语义：`rst_n` 用于系统复位；`clear` 用于开始新的累加任务；`in_valid = 1` 时累加，`in_valid = 0` 时保持 accumulator。
- 已理解 pipeline 的 cycle、stage、latency 和 throughput 区别；真实 pipeline MAC 的 valid 对齐和 RTL 实现尚未开始。
- 两级流水线中，若乘积写入 `product_reg`，就需要配套的 `product_valid`：在输入采样时执行 `product_valid <= in_valid`，下一拍由 accumulator 使用上一拍的 `product_reg` 和 `product_valid`。这是一拍寄存器延迟，不是由阻塞赋值“天然产生”的。
- 若没有 `product_reg`，则可以直接用 `in_valid` 控制同一时序阶段的累加；引入寄存器后，数据和 valid 必须一起延迟。若进一步采用 ready/valid，还应以 `fire = in_valid && in_ready` 作为真正被接收的条件。
- `clear` 不能只清 accumulator；带流水线时还要考虑清除或冲刷流水线中的 valid，避免旧乘积在新任务中被累加。
- 已理解 self-checking Testbench 的基本结构：用参考模型维护 expected result，自动与 DUT 输出比较，而不只依赖波形观察。
- 后续 testbench 应覆盖正常累加、`in_valid = 0` 保持、`clear`、signed 边界和 pipeline latency。

## 我的理解

> INT8 × INT8 的单次完整乘积是 INT16；使用 INT32 的主要原因是为多次累加保留位宽，不是因为单次乘法直接生成 INT32。同一组 bit 只有在声明为 signed 并正确符号扩展后，才能在 MAC 数据通路中保持预期的负数含义。MAC 的 accumulator 是状态；`clear` 决定一次新累加从何处开始，`in_valid` 决定某一拍是否真的发生累加。
